# 暗号文と鍵の形式

この形式は実装から独立して読めるように書いている。形式を変えるときは版を上げる。

| 版 | 出力 | 復号 | 備考 |
|---|---|---|---|
| `sf2` | v0.2.0〜 | ○ | 複数の宛先、添付ファイル |
| `sf1` | v0.1.0 のみ | ○ | 宛先1つ。互換のため復号だけ続ける |

## 暗号方式

| 部品 | 方式 |
|---|---|
| 宛先ごとの鍵の受け渡し | HPKE（RFC 9180）Base モード。KEM は X-Wing（X25519 + ML-KEM-768）、KDF は HKDF-SHA256、AEAD は AES-256-GCM |
| 本文 | AES-256-GCM（使い捨ての 32 バイト鍵 DEK） |
| HPKE の info | sf2: UTF-8 の `sealform/v2`、sf1: `sealform/v1` |

実装には `@hpke/core` と `@hpke/hybridkem-x-wing`、Web Crypto を使い、暗号部品は自作しない。

sf2 は、本文を DEK で1回だけ暗号化し、DEK を宛先の鍵ごとに HPKE で包む（KEM-DEM 構成）。宛先が増えても本文は1つで済む。

## 文字列の暗号文（sf2）

```
sf2.<meta>.<宛先一覧>.<本文>
```

| 部分 | 中身 |
|---|---|
| `meta` | base64url（パディング無し）で包んだ UTF-8 の JSON: `{"v":2,"f":"<フォーム識別子>","n":"<項目名>","t":<UNIX 秒>,"k":"text"}` |
| `宛先一覧` | 宛先ごとに 1176 バイトを並べ、base64url にしたもの。1 件 = `kid`（8 バイト）‖ HPKE の enc（1120 バイト）‖ 包んだ DEK（48 バイト）。最大 10 件 |
| `本文` | `iv`（12 バイト）‖ AES-256-GCM 暗号文 を base64url にしたもの |

- `kid` は X-Wing 公開鍵（1216 バイト）の SHA-256 の先頭 8 バイト。
- DEK を包むときの AAD: `sf2.<meta>` の UTF-8。
- 本文の AAD: `sf2.<meta>.<宛先一覧>` の UTF-8。宛先フォーム・項目名・時刻・種類・宛先一覧のどれを書き換えても、本文の復号に失敗する（宛先を一部消して受け取り手を偽ることもできない）。
- 平文は「4 バイト（ビッグエンディアン）の長さ ‖ UTF-8 本文 ‖ 0 埋め」で、64 バイトの倍数に丸める。

## 添付ファイル（sf2f）

```
"sf2f"（4 バイト） ‖ head の長さ（u32 ビッグエンディアン） ‖ head ‖ iv（12 バイト） ‖ AES-256-GCM 暗号文
```

- `head` は `sf2.<meta>.<宛先一覧>` の UTF-8（`meta` の `k` は `"file"`）。DEK の包み方と AAD は文字列と同じ。
- 平文は `u32 の長さ ‖ {"name":"<元のファイル名>","type":"<MIME>"} ‖ ファイル本体` を、4096 バイトの倍数に丸めたもの。**元のファイル名と種類も暗号文の中に入る。**
- 送信時のファイル名は `sealed-<16 桁の16進>.sf`、種類は `application/octet-stream`。
- 上限は暗号化前 50MB（フォームごとに `data-sealform-max-mb` で下げられる）。

`k`（種類）を AAD に含めているので、文字列の暗号文とファイルを取り違えることはできない。

## 文字列の暗号文（sf1、復号のみ）

```
sf1.<kid>.<meta>.<enc>.<ct>
```

`meta` は `{"v":1,"f","n","t"}`。HPKE で平文を直接暗号化し、AAD は `sf1.<kid>.<meta>`。

## 公開鍵

### 1人分の公開鍵（keygen が出力する）

```json
{
  "sealform": 1,
  "kid": "23662db0cbd499e5",
  "alg": "HPKE-Base/X-Wing/HKDF-SHA256/AES-256-GCM",
  "publicKey": "<base64url>",
  "fingerprint": "SHA256:<公開鍵の SHA-256 を base64（パディング無し）>",
  "created": "2026-10-12T00:00:00.000Z",
  "expires": "2027-10-12T00:00:00.000Z",
  "label": "相談員A"
}
```

`label` は任意。読み込むときは `kid` と `fingerprint` を鍵本体から計算し直して照合する。

### 鍵の束（サイトの `/.well-known/sealform-key.json`）

```json
{ "sealform": 1, "type": "key-set", "keys": [ <1人分の公開鍵>, ... ] }
```

- ブラウザは、束のうち**有効期限内の鍵すべて**に宛てて暗号化する。期限切れの鍵は使わない。
- 有効な鍵が 0 個、10 個を超える、同じ鍵が重複する、のいずれかなら暗号化しない。
- 指紋を固定している場合（`data-sealform-fingerprint` に空白区切りで並べる）、使う鍵の**すべて**が固定値に含まれていなければ暗号化しない。攻撃者が自分の鍵を束に足して写しを受け取ることを防ぐ。
- 1人分の公開鍵の JSON をそのまま置いてもよい（v0.1 の形式）。

### 鍵の更新

1. 新しい鍵を `keygen` し、束に `keys add` する（この間は新旧の両方に宛てて暗号化される）
2. HTML の `data-sealform-fingerprint` と `check --fingerprint` に新しい指紋を足す
3. 古い鍵を `keys remove` し、指紋の登録からも外す
4. 古い秘密鍵は捨てずに保管する。`open --key 新 --key 旧` のように並べれば、古い暗号文も開ける

## 秘密鍵ファイル

```json
{
  "sealform": 1,
  "type": "private-key",
  "kid": "...",
  "publicKey": "<base64url>",
  "kdf": { "alg": "argon2id", "m": 19456, "t": 2, "p": 1, "salt": "<16 バイト>" },
  "iv": "<12 バイト>",
  "ciphertext": "<X-Wing 秘密鍵（32 バイトの種）を AES-256-GCM で暗号化したもの>"
}
```

- 鍵: Argon2id(NFC 正規化したパスフレーズ, salt, m, t, p) → 32 バイト
- AAD: `sealform-private-key.<kid>`
- 開くときは `kid` を公開鍵から計算し直し、`m > 1 GiB` などの極端な値は拒否する。

## 紙の復旧コード

```
SFR1-XXXX-XXXX-…（4 文字ずつ 15 組、最後の組は 2 文字）
```

- 中身: Crockford Base32（`0123456789ABCDEFGHJKMNPQRSTVWXYZ`）で書いた `種（32 バイト） ‖ 検査値（4 バイト）`。
- 種: X-Wing の秘密鍵（32 バイト）そのもの。**パスフレーズ無しで秘密鍵になる。**
- 検査値: `SHA-256("sealform-recovery-v1" ‖ 種)` の先頭 4 バイト。書き写しの誤りを検出する。
- 読み取りでは、区切り・空白・大文字小文字の違いを無視し、`I`/`L` は `1`、`O` は `0` と読む。
- 公開鍵・kid・指紋は種から計算し直せる（X-Wing の決定的な鍵生成）。復旧したら、印刷した kid・指紋と一致するか確かめる。

## 形式に含まれないこと（実装の約束ごと）

- **空欄。** ブラウザは空の値を暗号化せず、空のまま送る（v0.4.0〜）。サーバー側の必須チェックを働かせるため。そのため、どの欄が空だったかはサーバーに分かる。
- **再送（リプレイ）。** 暗号文には送信ごとの使い捨ての番号を入れていない。同じフォーム・同じ項目に、過去の暗号文をもう一度送ることはできる。見出しに入る宛先フォームと項目名は、**別フォーム・別項目への転用**を検出するためのもの。重複を避けたいときは、受け取る側で暗号文のハッシュを記録して重複を拒否する。
- **サーバー側の検証（isSealed / isSealedFile）。** 見出しの JSON、種類（`text` / `file`）、宛先一覧の長さ（1176 バイトの倍数・10 件まで）、本文の長さ（iv 12 バイトと認証タグ 16 バイトを除いて、文字列は 64 バイト・ファイルは 4096 バイトの倍数）を確かめる。**確かめるのは形だけ**で、暗号文が本物かは秘密鍵で復号するまで分からない。Node・PHP・Python の結果は `test-vectors/validator.json` で一致させている。
