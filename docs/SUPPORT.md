# 対応環境と保守方針

## 保守方針

- sealform は**試作段階（0.x）**です。暗号の専門家による第三者レビューはまだ受けていません。
- 修正（セキュリティ修正を含む）は**最新の版にだけ**行います。古い版へのさかのぼっての修正はしません。
- 0.x のあいだは、小さい版（0.3 → 0.4 など）で互換性のない変更をすることがあります。その場合は [CHANGELOG.md](../CHANGELOG.md) に明記します。
- **暗号文の形式は互換性を保ちます。** 古い版で作った暗号文は新しい版でも復号できるようにします（v0.1 の `sf1` も復号できます）。形式を変えるときは版の記号（`sf2` など）を上げます。
- 配布物（`sealform.js`）のハッシュは版ごとに [hashes.json](../hashes.json) に記録し、`sealform check` が照合します。同じ版の中身は変えません。
- 脆弱性の報告と対応の目安は [SECURITY.md](../SECURITY.md) を見てください。

## 対応環境

「CI で確認」は、push のたびに GitHub Actions で自動テストしているものです。

### ブラウザ（フォームに組み込む sealform.js）

| ブラウザ | 状況 |
|---|---|
| Chromium（Chrome・Edge） | CI で確認（Playwright で実際に送信し、届いた中身を検査） |
| Firefox | CI で確認（同上） |
| WebKit（Safari のエンジン） | CI で確認（同上）。**Safari 本体・iOS Safari の実機は未確認** |
| JavaScript が無効なとき | CI で確認（送信ボタンが押せず、Enter でも送られない） |

必要な機能: Web Crypto（`crypto.subtle`）。添付ファイルを暗号化するときは `DataTransfer` も必要です。
どちらかが無いブラウザでは、送信できない状態になります（平文では送りません）。
スマートフォンでの性能は実機で測っていません。

### サーバー・ツール

| もの | 対応 | 確認のしかた |
|---|---|---|
| Node.js（CLI・ライブラリ） | 20.19.0 以上 | CI で 20 / 22 / 24 |
| PHP の検証関数（`server/php/sealform.php`） | 7.4 以上 | CI で 7.4 |
| Python の検証関数（`server/python/sealform_check.py`） | 3.9 以上 | CI で 3.9 |

### WordPress プラグイン

| もの | 対応 | 確認のしかた |
|---|---|---|
| WordPress | 7.1 で確認 | CI で WordPress 7.1 + Contact Form 7 6.2.2 を Docker で立てて、実際に送信 |
| Contact Form 7 | 6.x | 6 系の「スキーマ」による検査に合わせています。5 系以前は未確認 |
| PHP | 7.4 以上 | 構文の確認は CI で 7.4、動作の確認は 8.3 |

CI の WordPress のテストで確かめていること: 添付ファイル付きの送信、必須の空欄、任意の空欄、平文の直接送信の拒否、公開鍵がすべて期限切れのとき、鍵の束が空のとき。

Contact Form 7 以外のフォームプラグインには対応していません。テーマで自作したフォームには、`sealform_form_attributes()` で属性を出力して使えます（必須チェックや平文の拒否は自分で書く必要があります）。
